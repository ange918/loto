Crée une application web complète appelée "InventairePro" — un outil de comptage d'inventaire terrain pour bars et restaurants au Bénin. L'utilisateur se rend dans les réserves de ses clients et compte les casiers et bouteilles de boissons (bières, sodas, eaux) avec son smartphone.

Stack : React 18 + Vite + TypeScript + Tailwind CSS + Supabase + React Router v6

Design : dark utilitaire — fond #0A0A0A, surfaces #141414 et #1E1E1E, accent vert #00C96B, texte blanc pur. Typographie : Unbounded (titres/labels) + Montserrat (corps). Zéro border-radius arrondi excessif, zéro UI library externe (pas de Shadcn, pas de MUI). Interface pensée pour le pouce sur mobile.

APP.TSX — Routing

Routes :
- /login → LoginPage (si non authentifié)
- / → DashboardPage (liste clients)
- /clients/nouveau → NouveauClientPage
- /inventaire/:clientId → InventairePage
- /historique/:clientId → HistoriquePage

Protéger toutes les routes sauf /login. Rediriger vers /login si session absente. Utiliser useEffect + supabase.auth.getSession() pour vérifier la session au montage.

PAGE INVENTAIRE (InventairePage.tsx)

Paramètre URL : clientId

Au montage :
1. Charger le client : supabase.from('clients').select('*').eq('id', clientId).single()
2. Charger tous les produits actifs : supabase.from('produits').select('*').eq('actif', true).order('categorie').order('nom')
3. Initialiser un state lignes : Record<string, { casiers: number, bouteilles: number }> avec produit_id comme clé, valeurs à 0

Affichage :
- Header : nom du client + date du jour (format DD/MM/YYYY) + bouton ← retour
- Grouper les produits par catégorie (bière, malt, soda, eau)
- Pour chaque catégorie : titre de section en Unbounded vert #00C96B uppercase + séparateur

ProduitRow.tsx — pour chaque produit :
- Fond #141414, padding confortable pour les doigts
- Nom du produit en Unbounded blanc sur une ligne
- Sous le nom en Montserrat gris : "1 casier = X bouteilles"
- Deux zones de saisie côte à côte :
  * Gauche : label "CASIERS" + input number (min=0, clavier numérique : inputMode="numeric")
  * Droite : label "VOLANTES" + input number (min=0, inputMode="numeric")
- Inputs : fond #0A0A0A, bordure #333, texte blanc, taille 20px, centré, largeur 80px, hauteur 56px (adapté au pouce)
- Si casiers > 0 ou bouteilles > 0 : afficher le total calculé en vert : "= X bouteilles"

Bouton "VALIDER L'INVENTAIRE" :
- Fixé en bas de l'écran, pleine largeur, fond #00C96B, texte noir Unbounded
- Au clic : filtrer les lignes où casiers > 0 ou bouteilles > 0
- Si aucune ligne remplie : afficher message d'erreur "Aucune quantité saisie"
- Sinon : insérer dans Supabase avec upsert (pour gérer les doublons du même jour) :

supabase.from('inventaires').upsert(
  lignesFiltrées.map(l => ({
    client_id: clientId,
    produit_id: l.produit_id,
    date_inventaire: new Date().toISOString().split('T')[0],
    casiers: l.casiers,
    bouteilles: l.bouteilles
  })),
  { onConflict: 'client_id,produit_id,date_inventaire' }
)

Après succès : afficher un message de confirmation "Inventaire sauvegardé ✓" en overlay vert 2 secondes, puis rediriger vers /.

PAGE HISTORIQUE (HistoriquePage.tsx)

Paramètre URL : clientId

Charger les inventaires du client groupés par date :
supabase
  .from('inventaires')
  .select('*, produits(nom, bouteilles_casier, categorie)')
  .eq('client_id', clientId)
  .order('date_inventaire', { ascending: false })

Afficher par date (la plus récente en premier) :
- En-tête de date en Unbounded blanc : "Inventaire du DD/MM/YYYY"
- Pour chaque ligne : nom produit + "X casiers + Y volantes = Z bouteilles" (Z = casiers * bouteilles_casier + bouteilles)
- Grouper par catégorie à l'intérieur de chaque date

Si aucun historique : "Aucun inventaire enregistré pour ce client."

POINTS IMPORTANTS

- Tout le texte des labels et titres : font-unbounded
- Tout le texte de contenu/body : font-montserrat
- inputMode="numeric" sur tous les champs de quantité pour ouvrir le clavier numérique sur mobile
- Pas de scroll horizontal, layout 100% mobile-first max-w-md centré sur desktop
- Les inputs de quantité doivent être larges et hauts (min 56px) pour être facilement cliquables avec le pouce
- Gestion des états loading et error sur chaque page
- Ne jamais laisser l'utilisateur sans feedback visuel après une action
